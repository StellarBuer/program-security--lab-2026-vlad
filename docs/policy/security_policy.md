## 1. Purpose
Метою цієї політики є встановлення обов'язкових правил безпечної розробки серверної та клієнтської частини **Tactics Game Engine**, захисту автентифікації користувачів (модуль `Identity`), захисту ігрової логіки та запобігання несанкціонованій модифікації ігрового процесу[cite: 8, 16, 18, 19].

## 2. Scope
Політика поширюється на весь вихідний код у пакці `src/` (шари Domain, Application, Infrastructure, API) та `clients/`, конфігураційні файли, сценарії міграцій БД, а також CI/CD пайплайни[cite: 8, 16, 19]. Вимоги є обов'язковими для розробника та ШІ-агентів, що генерують код[cite: 8].

## 3. Roles and Responsibilities
- **Розробник / Архітектор (Vladyslav):** Відповідає за дотримання принципів Clean Architecture, захисту серверної логіки та розгортання компонентів[cite: 8, 16, 19].
- **Рев'юер:** Перевіряє код перед злиттям у магістральну гілку (особливо критичні зміни в модулях автентифікації та бойової логіки)[cite: 8, 18].

## 4. Security Principles
- **Server Authority (Серверний авторитет):** Клієнт є недовіреним середовищем. Будь-які розрахунки бою, нарахування досвіду та перевірки ходів виконуються виключно на сервері[cite: 16, 19].
- **Least Privilege (Мінімальні привілеї):** Доменний шар (`Game.Domain`) ізольований від інфраструктурних деталей (EF Core, ASP.NET Core).
- **No Secrets in Source Code:** Заборонено жорстко кодувати JWT-секрети, рядки підключення до БД (Connection Strings) чи ключі шифрування у вихідному коді або історії Git[cite: 8, 16].
- **Deny by Default:** Усі запити до захищених API-ендпоїнтів за замовчуванням вимагають валідного JWT-токена[cite: 8, 19].

## 5. Secure Development Environment
- Прямі коміти у гілку `master` заборонені; робота ведеться через гілки функціоналу та Pull Requests[cite: 8].
- Конфігураційні секрети передаються через змінні середовища (Environment Variables) або `dotnet user-secrets`[cite: 8].
- Зовнішні NuGet-пакети проходять перевірку на наявність відомих вразливостей (Roslyn Analyzers / Dotnet Vulnerability Scanning)[cite: 8, 16].

## 6. Secure Implementation
- **Валідація вхідних даних:** Усі вхідні параметри команд (Commands) та запитів (Queries) у шарі Application проходять валідацію до передачі в доменний шар[cite: 15, 16].
- **Криптографія:** Паролі користувачів хешуються із застосуванням криптографічно стійких алгоритмів з солюванням (наприклад, ASP.NET Core PasswordHasher / Argon2/BCrypt)[cite: 16, 19].
- **Обробка помилок:** Системні винятки та помилки бази даних перехоплюються на рівні API та не розкривають внутрішню структуру стеку чи таблиць БД. Усі помилки успадковуються від базового `AGameEngineException`[cite: 15, 16].

## 7. Security Verification
- Юніт-тести (xUnit) покривають 100% бізнес-правил доменного шару (розрахунок ходів у бойовій сітці 5x5, перевірка інваріантів)[cite: 16, 19].
- Перевірка статичним аналізатором коду перед кожним релізом.

## 8. Vulnerability Management
- Виявлені вразливості та баги в бізнес-логіці фіксуються в changelog та усуваються в пріоритетному порядку[cite: 17].

## 9. Final Provisions
- Ця політика підлягає перегляду у разі зміни архітектури чи додавання нових модулів (Bounded Contexts)[cite: 8, 18].
